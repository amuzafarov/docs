Every time a Synclify sync runs — whether triggered by a schedule or manually — it follows the same four-stage pipeline: connect to your data source, read the latest rows, transform each row according to your saved field mapping, and write the results to your Webflow CMS Collection via the Webflow API. Understanding this pipeline helps you configure mappings correctly, troubleshoot errors, and set realistic expectations about what Synclify does and does not do with your data.

## The sync pipeline

<Steps>
  <Step title="Connect Webflow">
    Synclify authenticates with your Webflow account using the OAuth connection you granted during setup. It identifies the target CMS Collection and reads its field structure — names, types, and slugs — so it knows exactly what shape the incoming data needs to take.
  </Step>
  <Step title="Pick your data source">
    Synclify authenticates with your chosen source — Google Sheets, Airtable, or Notion — and fetches the latest snapshot of your data at the moment the sync runs. For Google Sheets, this means every row below the header row. For Airtable, every record in the selected table. For Notion, every entry in the selected database. Your source data is read once per sync and is never stored on Synclify's servers between runs.
  </Step>
  <Step title="Map your fields visually">
    Synclify applies the field mapping you configured in the visual mapper. Each source column is paired with a target Webflow CMS field. Values are cast to the correct type — plain text, rich text, image URL, number, date, or option — and validated against Webflow's field constraints before any write is attempted.
  </Step>
  <Step title="Sync automatically">
    Transformed rows are written to your Webflow CMS Collection using the Webflow API. New rows that don't yet exist as Collection items are created; rows that match an existing item by slug or a designated unique key are updated in place. The sync engine processes rows in batches and logs the outcome of every single row — success, skip, or error.
  </Step>
</Steps>

## Data flow

When a sync runs, Synclify reads your source data in real time, transforms it in memory using your saved field mapping, and writes the results directly to Webflow CMS. **Your source data is never stored on Synclify's infrastructure.** It exists in memory only for the duration of the sync job and is discarded immediately afterward. OAuth credentials for both your Webflow account and your connected sources are encrypted at rest using AES-256-GCM and transmitted exclusively over TLS 1.3.

## Sync modes

Synclify supports two ways to trigger a sync for any connection.

**Scheduled sync** runs automatically at a fixed interval you choose:

- **Hourly** — runs once every 60 minutes
- **Daily** — runs once per day at a time you specify
- **Weekly** — runs once per week on a day and time you choose
- **Custom** — enter a cron expression for full control over timing

**Manual sync** lets you trigger a sync on demand at any time by clicking **Sync Now** on a connection card in the agency dashboard or the client portal. Manual syncs run through the same pipeline as scheduled syncs and produce the same log output.

## What gets synced?

Each row in your spreadsheet, table, or database corresponds to one item in your Webflow CMS Collection. Synclify maps source rows to Collection items as follows:

- **New rows** — if a source row has no matching CMS item, Synclify creates a new Collection item using the mapped field values.
- **Updated rows** — if a source row matches an existing CMS item (matched by slug or a unique key field you designate), Synclify updates that item with the latest values from the source.

All other CMS items — items that have no corresponding row in the source — are left exactly as they are. Synclify will never delete a CMS item as part of a sync.

<Info>
  Synclify only **creates** and **updates** Webflow CMS items. It does not delete items, even if you remove a row from your source spreadsheet or database. To remove a CMS item, delete it directly in Webflow or via the Webflow Designer.
</Info>

## Error handling

Synclify validates every row before writing it to Webflow. If a row fails validation — for example, a required field is blank, a value exceeds the allowed length, or an option value doesn't match an existing Webflow option — that row is **logged and skipped**. The sync continues processing all remaining rows, so a single bad row never blocks the rest of your data from syncing.

After a sync completes, the Sync Log shows a summary of rows created, updated, skipped, and failed. For any failed rows, Synclify records the field name, the offending value, and the reason for the failure. You can download the full error list as a **CSV error report** from the Sync Log tab, making it easy to share with a client or import into your own QA workflow for correction.
