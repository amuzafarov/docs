The wizard creates a draft. Guided setup is what happens next — the part that keeps Synclify from trampling data you already have.

Most collections aren't empty when you connect them. There are Airtable rows with no Webflow item, Webflow items with no row, and records on both sides whose values disagree. Guided setup resolves all three before the first sync writes anything.

## 1. Auto pairing

Synclify matches existing source rows to existing Webflow items on the [identity field](/how-synclify-works#the-identity-field), using exact matches only. The matched records are shown in a table for you to check.

<Note>
  **"Auto-pair is not available for this draft — Save the required existing-data decision instead."**

  Not an error. Some drafts can't be auto-paired; skip to the decisions below and Synclify proceeds normally.
</Note>

## 2. Record decisions

Whatever didn't pair needs a decision. You get up to two, and each is required if its count is above zero.

<AccordionGroup>
  <Accordion title="Source rows with no matching Webflow item" icon="arrow-right">
    _"N source rows ready to sync, but Webflow has no matching CMS items."_

    Choose **Create Webflow items**. Synclify creates a CMS item for each on the first sync.
  </Accordion>

  <Accordion title="Webflow items with no matching source row" icon="arrow-left">
    Two choices, and you pick one:

    - **Leave them alone** _(recommended)_ — _"The items stay in "_{collection}_" exactly as they are. This connection never edits or deletes them."_
    - **Import them into "**{source}**"** — _"Synclify creates matching rows in "_{source}_", then keeps both sides in sync."_

    Leaving them alone is the default and usually the right one — those items are typically older content that predates your source table. Import is for the opposite case: the Webflow collection is the content you want to start managing from the source.
  </Accordion>
</AccordionGroup>

<Note>
  This step appears **even when the source table is empty**. An empty source and a full collection is exactly the situation where the import decision matters most, so Synclify asks rather than assuming.
</Note>

Your choice is saved with the draft and restated on the first-sync step and on the connection page, so it is never a decision you made once and cannot see again.

### Reading the dry-run summary

The preview counts what the planner plans. Record decisions are promises about what the first sync will write, so a summary that ignored them could read _"0 planned changes"_ while the review card above it promised to import a dozen items.

It doesn't. The summary appends the pending writes:

> 2 imports into Airtable pending 3 creates in Webflow pending

These notes appear in both the summary text and the dialog's counts line, and they survive a page reload. **Leave them alone** contributes nothing to the count, because it writes nothing.

## 3. Conflicts

For records paired on both sides whose values disagree, Synclify asks who wins: the source, or Webflow.

It won't guess. Pick per conflict, then continue. Details on how conflicts work in general: [Conflicts](/syncing/conflicts).

## 4. Preview and approve the first sync

Synclify computes the complete first sync — every page of it — and shows you what it will do: which items get created, which get updated, which get deleted, which get skipped.

Read it. This is the last checkpoint before Webflow changes.

**Approve** activates the connection.

<Note>
  **Warnings do not block activation.** Validation results that are warnings — including _"dry-run preview is only available"_ — let you proceed, with a toast. Only genuine errors (`error`, `failed`, `invalid`) block. If a warning looks material, cancel and investigate rather than clicking through.
</Note>

## 5. First sync

The manual sync fires automatically the moment the connection activates. Its direction follows what your mapped fields allow — see [the direction you actually get](/how-synclify-works#the-direction-you-actually-get).

You'll see: _"Your connection is active now. The first sync has started automatically."_ After a 10-second countdown you're redirected to the connection page, where you can watch the live phases.

## If setup stalls

<AccordionGroup>
  <Accordion title="'Existing-data decisions are not available for this draft'">
    The full message tells you what to do: recheck the draft after the mapping update. If validation still reports unpaired records, resolve them in the Airtable table or in Webflow directly, then return.

    Usually means the identity field can't match anything — check that the column you chose actually holds the same values on both sides.
  </Accordion>

  <Accordion title="'This conflict type has no self-serve resolution'">
    Contact support. Some conflicts need backend intervention.
  </Accordion>

  <Accordion title="Setup seems to hang on 'evaluating existing rows'">
    Expected on larger tables. Synclify retries automatically. Give it a moment.
  </Accordion>

  <Accordion title="Approve fails once, then works">
    If the preview was incomplete, Synclify re-runs it in full and retries the approval. No action needed.
  </Accordion>

  <Accordion title="You closed the tab mid-setup">
    Progress is saved. Reopen the connection and Synclify resumes at the stage you left.
  </Accordion>
</AccordionGroup>

## After activation

The connection is `active`. It syncs on source changes (realtime), on your polling schedule if you set one, and whenever you click **Sync now**.

To change anything about it from here — mapping, direction, cadence — you need [an editable draft](/connections/edit-a-connection).
